# Automation & Toil Reduction Opportunities

Identify repetitive manual tasks across the team that could be automated to reduce toil and improve developer productivity.

## Data Sources
- Taskei: Recurring task types, manual process tasks, tasks tagged as toil or ops
- CRUX CRs: Repetitive CR patterns (version bumps, config changes, boilerplate)
- Pipelines: Manual deployment steps, pre/post deployment checks done by hand
- Apollo: Manual intervention patterns in deployments
- Oncall system: Recurring incident types with manual remediation, frequent manual runbook steps
- Slack: Team complaints about repetitive work, "I wish this was automated" signals
- Calendar: Recurring meetings that exist only to coordinate manual handoffs

## Instructions
1. **Identify Toil from Taskei**:
   - Search for tasks that recur every sprint with similar descriptions
   - Look for tasks tagged as "ops," "maintenance," "manual," or "toil"
   - Identify tasks that multiple team members do independently (redundant effort)
   - Calculate total person-hours spent on recurring manual tasks per sprint
2. **Identify Toil from CRs**:
   - Look for CR patterns that repeat: dependency bumps, config file updates, boilerplate additions
   - Identify CRs that could be generated by tooling (version updates, API client regeneration)
   - Check for manual steps in CR descriptions that could be scripted
3. **Identify Toil from Operations**:
   - Review oncall system for incidents with the same manual remediation steps
   - Check for alarms that always require the same manual intervention
   - Identify deployment steps that require human judgment but could be codified
   - Look for manual health checks that could be automated monitors
4. **Identify Toil from Communication**:
   - Check for Slack messages that are essentially manual status broadcasts
   - Look for meetings that exist only because automated reporting doesn't exist
   - Identify manual cross-team coordination that could be automated with tooling
5. **Prioritize Opportunities**:
   - For each opportunity, estimate:
     - Current time cost (hours/month across team)
     - Automation effort (T-shirt size: S/M/L/XL)
     - Risk reduction value (does it prevent incidents?)
     - ROI timeline (when does automation pay for itself?)
6. **Recommend Solutions**:
   - For each opportunity, suggest implementation approach
   - Identify existing tools/frameworks that could be leveraged
   - Suggest who on the team might enjoy building it (growth opportunity)
